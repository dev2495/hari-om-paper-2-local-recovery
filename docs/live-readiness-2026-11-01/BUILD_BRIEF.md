## Owner decisions (binding)

1. **Short close at any stage (batch-entry V2 cards; old V1 cards aligned where they still run).** The output already logged moves downstream; the job card stays open until every downstream stage has logged and closed with its outputs. A stage closed short cuts the downstream targets to what it actually passed on. **The unmade balance goes back to the sales order line at once** as unreleased qty, so Sales can release it again or short close the order with a reason. Rule for the balance: at each short close return `(this stage's target in pcs) − (this stage's good output in pcs)`; the sum of all returns + final FG must equal the released qty (invariant, tested). Reopening a short-closed stage reverses its return where possible (or blocks reopen with a clear message if the balance was already re-released or short-closed) and restores downstream targets. Downstream planner slots shrink to the new target automatically. Card history shows "closed short" with qty and reason. Order page, job card list, card manager "Back to order", fulfilment bars and reports must all agree.
2. **Partial output becomes FG and can ship.** Pieces are packed in **boxes at the end of Process** and **the box is the dispatch unit**. As Process good pcs are logged (and the run's QC readings are done; QC only flags, it never holds), the system packs them into boxes using the spec's box and qty per box: each full box gets a unique box code and QR label and is posted as FG for that job card (with its packing material theory consumption). Leftover pcs carry to the next run; when Process closes, the remainder becomes a **part box** with its own QR label marked as a part box. The dispatch challan is built from boxes (scan box QR or tick boxes); the challan lists every box code, box count, pcs per box and total pcs, and its packing block comes from the spec (box code, qty per box). Partial dispatch = some of the card's boxes. The card completes when all its boxes are dispatched (or the surplus decision is made). Box label: plant heading, customer, product/spec, size, colour, job card no, SO no / customer PO, box code, pcs in box (part box marked), packed date and shift, operator, QR that opens the box page; printable as sticker labels (several per A4 and single label size), reprint never creates stock.
3. **Job card QC never holds or rejects.** In-process and final QC readings outside the band are **flagged** on the run, batch, lot, box and card (clearly visible everywhere), never automatic holds and never blocking dispatch. Remove automatic QC holds on job cards and V1 final-QC pass requirements for dispatch; keep the 2-readings-per-check rule for closing a stage. Manual holds that a plant head/Admin/Owner places on purpose stay as they are, and dispatch is blocked only by such deliberate movement-blocking holds. Incoming (GRN) QC is unchanged: out-of-band incoming lots are still held.
4. **Reasons: master codes only, everywhere.** Every place in the stack that asks for a reason must pick a code from the Reason codes master (with an optional note; codes whose code contains OTHER require a note of at least 5 characters). No free-text-only reasons anywhere. Add all needed categories and seed sensible codes for each (plus an OTHER code per category); the server validates the code (active, right category, right plant) in the owning service, not only in the BFF; records store code + label-at-the-time + note; reports and histories show the label. Existing data keeps its old text.
5. **Packing from masters.** The spec sheet's packing section picks the box, plastic and fadda from the Packaging masters; where only one active plastic or fadda master exists it is the default. Per-piece / per-unit weights come from the masters for theory consumption (no blank-weight rows silently dropped: warn instead). New specs cannot be approved without box + qty per box. A temporary **Packing setup** page (Owner/Admin; the owner's user Harish will use it) lists every active spec with its current packing and lets him set box (master), qty per box, plastic and fadda (defaulted) and their per-box counts row by row, saving straight to the spec without a full re-approval cycle (audited), and pushing the packing into open job cards that have not packed any box yet. Spec box codes not found in the master are highlighted with a link to add the box master. Fadda is the inside-box sheet (putha); no new item types for now.
6. **Reel and coil labels** match the plant's own label exactly, with a QR added and big clear letters, nothing more or less. Layout (from their Excel `reel printing.xlsx`, sheet "REEL PRINT."), one bordered label per reel:
   - Row 1: heading `AMIGO INDUSTRIES UNIT II` (from the plant: add a "label heading" on the plant master, default from its legal name, e.g. "AMIGO INDUSTRIES UNIT II").
   - Row 2: three cells: MILL NAME (vendor/mill short name, e.g. AKSHAT), supplier invoice no (e.g. 2525 or VPI/1686/2026-27), received date (dd-Mon-yy, e.g. 28-Oct-26).
   - Row 3 headers: PLYBOND | VARIETY | GSM. Row 4 values: polybond (400), variety = paper code (351), GSM as printed on their label (they print the variety number, e.g. 351; use the measured GSM if one was recorded at inward, else the variety code).
   - Row 5: ROLL NO. | mill's roll/reel no (65686).
   - Row 6: the Amigo serial in very large bold letters, e.g. `AIT 06243`.
   - Row 7: WEIGHT | weight kg (1161).
   - Plus the QR (scans to the reel page as today).
   - **Serial:** `AIT` + space + 5-digit number, one running series for reels per financial year, restarting at 00001 on 1 April. Because the plant is mid-year on its own series (last printed around AIT 06279), the Owner/Admin must be able to set the next number for the current year once (a small setting, audited). New reels/coils get the new serial; existing AT-… numbers stay valid and searchable. Coils slit from a reel use the parent serial plus a suffix (`AIT 06243-1`, `-2`…) and the coil's own weight; same layout. Opening-stock labels use the same layout and series.
7. **Operators.** Every floor log (output and QC, every stage, phone and PC) asks for the operator and lists only active employees of the department that runs that stage (Winding→winder dept, Oven→oven dept, Process→process dept; use the departments in Masters > Employees). Add an **Employee performance report** (Reports): per operator and date range/shift/stage: runs, made, good, rejected, reject %, flagged QC readings, hours/shifts worked; drill to runs; CSV export; for Owner/Admin/Plant Manager/Planner.
8. **Qty math must be gap-free and connected:** release → card → stage targets → runs → short closes/returns → boxes/FG → dispatch → order fulfilment → month-end theory. Add tests that walk full, partial, short and reopen scenarios end to end.
